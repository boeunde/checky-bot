# checky-bot 기획서

Nov 9, 2026 · @아크로버스

## 개요

checky-bot은 여러 Google 공유 캘린더의 일정을 여러 Slack 채널로 알려 주는 봇이며, 모든 설정을 Slack 안에서 합니다.

- **배경:** Slack의 Google Calendar 앱에서 캘린더를 채널에 연결하는 기능이 2026년 12월 15일에 종료됩니다. 개인 캘린더 연결만 남아 공용 채널 알림을 대신할 수 없습니다.
- **목표:** 채널 3개 이상, 공유 캘린더 여러 개를 봇 하나로 연결합니다. 관리자는 스크립트를 열지 않고 Slack에서 설정을 바꿉니다.
- **구성:** Slack 앱(봇 토큰 방식) + Google Apps Script. 별도 서버는 두지 않습니다.

- **범위 (v1.0.0):** 설치·관리자, 연결, 하루 요약, 일정 알림, 변경 알림(일정 등록/변경/삭제), 관리 기능, 장애 처리. 12월 15일 전 실사용이 목표입니다.

## 용어

| 용어 | 뜻 |
| --- | --- |
| 앱 설치자 | 봇 전체의 책임자. 설치 직후 처음 봇 설정을 연 사람이 등록됩니다. 장애 알림 DM을 받습니다. |
| 채널 봇 관리자 | 채널별로 지정되며, 그 채널의 연결과 설정을 바꿀 수 있는 사람입니다. 이 문서에서 "관리자"는 채널 봇 관리자를 뜻합니다. |
| 연결 | 채널 1개 + 캘린더 1개 + 알림 설정 묶음. 한 채널에 여러 캘린더를, 한 캘린더를 여러 채널에 연결할 수 있습니다. |
| 공용 구글 계정 | 스크립트가 돌아가는 계정. 연결할 캘린더는 모두 이 계정에 공유돼 있어야 합니다. |

## 사용자 흐름

설치부터 첫 알림까지 다섯 단계이며, 모든 단계는 Slack 안에서 끝납니다.

1. **설치:** 사용자A가 워크스페이스에 봇을 설치합니다. 워크스페이스 정책에 따라 Slack 관리자 승인이 필요할 수 있습니다. 처음 봇 설정을 연 사람이 앱 설치자로 등록됩니다.
2. **채널 초대:** 사용자A가 채널A에 봇을 초대합니다. 초대한 사람이 채널A의 첫 관리자가 됩니다.
3. **관리자 추가:** 사용자A가 채널A의 봇 설정에서 사용자B, C를 관리자로 추가합니다.
4. **캘린더 연결:** 관리자(A, B, C)가 채널A의 봇 설정에서 공유 캘린더 ID를 입력합니다.
   - 설정 화면에 "이 계정에 캘린더를 공유한 뒤 ID를 입력하세요"와 공용 구글 계정 주소를 보여 줍니다.
   - 공용 계정이 볼 수 없는 캘린더면 연결하지 않고 원인을 보여 줍니다.
5. **연결 확인:** 연결되면 앞으로 가장 가까운 일정 1개의 알림을 **연결한 관리자에게만** 보여 줍니다. 예정된 일정이 없으면 "연결되었습니다. 예정된 일정이 없습니다."를 보여 줍니다.

연결이 끝나면 관리자가 알림 루틴과 변경 알림을 설정합니다.

## 권한

관리자는 채널별이며, 채널A 관리자는 채널A의 연결만 바꿀 수 있습니다.

| 할 수 있는 일 | 앱 설치자 | 채널 관리자 | 일반 멤버 |
| --- | --- | --- | --- |
| 채널의 연결·설정 보기 | O | O | O |
| 연결 추가·변경·삭제·일시정지 | 그 채널 관리자일 때만 | O | X |
| 채널 관리자 추가·제거 | 그 채널 관리자일 때만 | O | X |
| 연결 상태 테스트 | 그 채널 관리자일 때만 | O | X |
| 오늘 일정 채널에 보내기 (`/checky today-all`) | 그 채널 관리자일 때만 | O | X |
| 오늘 일정 나만 보기 (`/checky today`) | O | O | O |
| 봇이 보낸 메시지 삭제 | 그 채널 관리자일 때만 | O | X |
| 장애 알림 DM 받기 | O | X | X |
| 앱 설치자 변경 | O | X | X |

- 채널마다 관리자가 최소 1명 남도록, 마지막 관리자는 빼지 못합니다.
- 게스트 계정과 다른 봇은 관리자가 될 수 없습니다.
- 누가 언제 무엇을 바꿨는지 변경 기록을 남기고, 설정 화면에서 최근 기록을 보여 줍니다.

## 알림 루틴

연결마다 하루 요약과 일정 알림을 따로 켜고 끌 수 있고, 둘 다 켜도 됩니다. 새 연결은 **하루 요약만 켜진 상태**로 시작합니다. 하루 요약, 일정 알림, 변경 알림 중 하나 이상은 켜져 있어야 합니다.

### 하루 요약

| 설정 | 선택지 |
| --- | --- |
| 보내는 시각 | 00:00\~23:59, 분 단위 (기본 오전 9:00) |
| 범위 | 모든 일정 / 종일 일정만 / 시간 일정만 |
| 요일 | 월\~일 중 여러 개 선택 |
| 일정이 없는 날 | 보내지 않음 / "일정 없음"으로 보내기 |

선택한 요일에 범위에 맞는 일정이 없으면, 관리자가 고른 대로 보내지 않거나 "오늘 일정 없음" 메시지를 보냅니다.

### 일정 알림

| 설정 | 선택지 |
| --- | --- |
| 시간 일정 알림 시점 (1개) | 시작 시간 / 5분 전 / 15분 전 / 30분 전 / 1시간 전 |
| 종일 일정 알림 | 켜짐 / 꺼짐 (기본 꺼짐). 켜면 알릴 시각을 정합니다: 그날 00:00\~23:59, 분 단위 (기본 오전 9:00) |
| 요일 | 월\~일 중 여러 개 선택 |

- 요일은 **일정이 있는 날** 기준입니다. 예: 요일을 월\~금으로 설정하면, 월요일 00:30 일정의 1시간 전 알림은 일요일 23:30에 발송됩니다. 일요일은 설정에 없지만, 일정이 월요일이기 때문입니다. 반대로 토요일 00:30 일정은 알림 시각이 금요일 23:30이어도 보내지 않습니다.
- 여러 날에 걸친 종일 일정은 날마다 알리고, 제목 뒤에 (1/2), (2/2)처럼 며칠째인지 붙입니다. 하루 요약에서도 같은 표시를 씁니다.
- 일정 시간이 바뀌면 바뀐 시간 기준으로 다시 알립니다.

## 변경 알림

일정 등록, 변경, 삭제를 채널에 알립니다. 마지막 변경 뒤 정한 시간 동안 조용하면 최종 결과만 보내, 입력 실수를 고치는 과정이 채널에 모두 보내지는 것을 막습니다.

연결의 ⚙️ 설정 화면에 세 번째 탭 **[✏️ 변경 알림]**을 추가해 정합니다. 새 연결은 **꺼진 상태**로 시작합니다.

변경 알림은 켜짐/꺼짐(기본 꺼짐) 아래에 **세트**를 둡니다. 기본은 세트 1개이고, **[+ 세트 추가]**로 최대 3개까지 늘립니다. 세트 2부터는 [삭제] 버튼으로 지웁니다. 세트마다 아래 항목을 똑같이 정합니다.

| 세트 설정 | 선택지 | 기본값 |
| --- | --- | --- |
| 요일 | 월\~일 중 여러 개 선택 (보내는 날 기준) | 월\~금 |
| 알림 종류 | 등록 / 변경 / 삭제, 각각 켜짐·꺼짐 | 모두 꺼짐 |
| 발송 시점 | 즉시 / 1분 / 3분 (마지막 변경 후 대기 시간) | 1분 |
| 과거 일정에 대한 변경 알림 | 알림 / 알리지 않음 | 알리지 않음 |
| 미설정요일 알림 모아보내기 | 켜짐 / 꺼짐. 켜면 모아 보내는 시각을 정합니다 (00:00\~23:59) | 꺼짐 (켜면 오전 9:00) |

변경 알림을 켜면 세트마다 알림 종류와 요일을 하나 이상 골라야 저장됩니다. **알림 종류마다 한 세트에만** 넣을 수 있어(겹치면 저장되지 않음) 알림 하나는 그 종류를 고른 세트의 설정을 따릅니다. 새 세트는 아직 어느 세트에도 없는 종류를 골라 둔 채로 추가됩니다. 세트가 생기기 전의 설정은 그대로 세트 1이 됩니다.

- **예:** 세트 1 = 월\~금, 등록·변경, 즉시 / 세트 2 = 금, 삭제, 즉시. 등록·변경은 평일에 바로 오고, 삭제는 금요일에만 옵니다. 세트 2의 모아보내기를 켜면 월\~목의 삭제는 금요일 정한 시각에 옵니다.
- **종류가 바뀐 경우:** 대기 중에 변경 → 삭제처럼 종류가 바뀌면 바뀐 종류의 세트를 따릅니다.
- **요약 줄:** 채널 설정 화면에 세트마다 한 줄씩 보입니다.

- **고르지 않은 요일:** 보낼 차례가 된 날이 고르지 않은 요일이면, "미설정요일 알림 모아보내기"가 꺼져 있을 때는 보내지 않습니다. 켜져 있으면 모아 두었다가 돌아오는 첫 요일의 정한 시각에 보냅니다(일정마다 메시지 하나). 예: 월\~금, 오전 9:00이면 토·일에 생긴 변경은 월요일 오전 9:00에 갑니다.

대기 시간 안에 또 바꾸면 그때부터 다시 기다립니다. 대기 시간이 1분일 때의 예시입니다.

| 대기 시간 안에 일어난 일 | 채널에 가는 알림 |
| --- | --- |
| 등록 → 오타 수정 | "등록" 1건 (최종 내용) |
| 등록 → 삭제 | 없음 |
| 등록 → 삭제 → 다시 등록 | "등록" 1건 (다시 등록한 내용) |
| 변경 → 변경 → 변경 | "변경" 1건 (최종 내용) |

- **변경의 범위:** 제목, 시간, 설명이 바뀐 경우만 "변경"으로 봅니다. 참석자의 초대 응답처럼 다른 것만 바뀌면 알리지 않습니다.
- **"변경" 알림의 내용:** 바뀐 뒤의 내용만 보여 줍니다. 바뀌기 전 내용은 보여 주지 않습니다.
- **과거 일정:** 이미 끝난 일정(삭제는 삭제 전 기준)의 등록·변경·삭제입니다. "알리지 않음"이면 보내지 않습니다. 과거 일정을 앞으로의 날짜로 옮기면 과거 일정이 아니므로 알립니다.
- **비공개 일정:** 다른 알림과 같이 보내지 않습니다. 공개 일정을 비공개로 바꾸면 "삭제"로, 비공개 일정을 공개로 바꾸면 "등록"으로 봅니다.
- **반복 일정:** 반복 일정 전체를 등록·변경·삭제하면 회차마다 알리지 않고 반복 일정 하나당 1건만 보냅니다. 따로 종류를 두지 않고 등록·변경·삭제 알림으로 보내며, 일정 줄에는 다음 회차를 적고, 아래 작은 회색 줄에 반복 규칙("매주 화요일, 13회")을 적습니다. 한 회차만 바꾸면("이 일정만") 일반 일정처럼 그 회차만 알립니다.
- **처음 켤 때:** 변경 알림을 켜거나 캘린더를 연결·변경한 시점의 일정은 기준으로만 저장하고 알리지 않습니다. 그 뒤의 변경부터 알립니다.
- **"즉시"의 뜻:** 구글이 변경을 알려 주는 데 몇 초에서 1\~2분이 걸리고, 봇은 1분마다 보낼 알림을 확인해서, 사실상 "가능한 빨리"입니다.
- **일정마다 따로 보내기:** 등록·변경·삭제 알림은 같은 시각에 보낼 차례가 되어도 묶지 않고 일정마다 메시지를 따로 보냅니다. 머리글에 "총 n건"도 붙이지 않습니다.

메시지 모양입니다. 변경 알림은 어느 날짜의 일정이든 올 수 있어 일정 줄에 날짜를 붙입니다.

```
일정 등록 | 디자인팀
┃ 11월 12일 (목) 14:00 - 15:00 주간 회의

일정 변경 | 디자인팀
┃ 11월 12일 (목) 15:00 - 16:00 주간 회의        ← 바뀐 뒤 내용

일정 삭제 | 디자인팀
┃ ~11월 12일 (목) 14:00 - 15:00 주간 회의~      ← 줄 전체 취소선, 삭제된 일정이라 링크 없음

일정 변경 | 디자인팀
┃ 11월 17일 (화) 10:00 - 10:30 스탠드업          ← 반복 일정 전체 변경, 다음 회차 기준
┃ 매주 화요일, 13회                              ← 작은 회색 글씨
```

## 메시지 형식

모든 알림은 제목과 시간만 기본으로 보여 주고, 설명은 있을 때만 보여 줍니다.

| 항목 | 표시 |
| --- | --- |
| 제목 | 항상 |
| 시간 | 항상. 종일 일정은 "종일" |
| 반복 규칙 | 반복 일정일 때만. 구글 캘린더처럼 "매주 화요일, 13회", "매월 둘째 화요일, 2026년 12월 31일까지"로 적습니다. 문장으로 만들 수 없는 규칙은 "반복 일정". 작은 회색 글씨 |
| 설명 | 있을 때만. 서식을 없애고 일반 글자로, 반복 규칙 아래 작은 회색 글씨. 300자가 넘으면 앞부분만 |
| 장소, 참석자, 회의 링크 | 표시하지 않음 |

머리글은 색 막대 없이, 일정마다 캘린더 색 막대를 붙이고 제목에 일정 링크를 겁니다. 같은 캘린더에서 같은 시각에 보낼 알림은 한 메시지로 묶습니다.

```
오늘 요약 | 11월 9일 월요일 | 디자인팀 | 총 2건
┃ 종일 창립기념일
┃ 14:00 - 15:00 주간 회의

일정 알림 | 디자인팀 | 총 1건
┃ 14:00 - 15:00 주간 회의
```

보내지 않는 일정은 두 가지입니다.

- **비공개 일정:** 캘린더에서 공개 범위가 "비공개"인 일정
- **세부정보를 볼 수 없는 일정:** 공용 구글 계정이 "한가함/바쁨"만 볼 수 있어 제목이 없는 일정

## 관리 기능

관리자는 연결을 테스트·삭제·일시정지하고, 봇이 보낸 메시지를 지울 수 있습니다.

| 기능 | 동작 |
| --- | --- |
| 연결 상태 테스트 | 일정이 있었던 가장 최근 지난 하루의 알림을, 그 연결의 현재 설정 형식(하루 요약, 일정 알림)으로 보여 줍니다. 버튼을 누른 관리자에게만 보이며, 실제 알림과 같은 모양입니다. |
| 오늘 일정 보기 | `/checky today`는 나에게만 보이게, `/checky today-all`은 채널에, 그 채널에 연결된 캘린더(일시정지 제외)의 오늘 일정을 하루 요약 모양으로 보냅니다. 하루 요약 설정(범위, 요일, 켜짐/꺼짐)과 관계없이 모든 일정을 보여 주고, 일정이 없는 캘린더는 "일정 없음"으로 표시합니다. |
| 연결 삭제 | 한 번 더 확인한 뒤 지웁니다. |
| 연결 일시정지 | 설정은 그대로 두고 알림만 멈춥니다. 관리자가 재개합니다. |
| 메시지 삭제 | 봇 메시지의 ⋯ 메뉴에서 "checky-bot 메시지 삭제"를 고릅니다. 그 채널 관리자가 아니면 실행되지 않습니다. 봇이 보낸 메시지만 지울 수 있습니다. |

## 장애 처리

알림이 실패하면 앱 설치자에게 DM을 보내고, 같은 문제로 반복해서 보내지는 않습니다.

| 상황 | 처리 |
| --- | --- |
| 캘린더 권한이 사라짐 | 그 연결의 알림을 건너뛰고 앱 설치자에게 DM을 보냅니다. 권한이 돌아오면 자동으로 다시 보냅니다. |
| 봇이 채널에서 내보내짐 | 그 채널의 연결을 모두 일시정지하고 앱 설치자에게 DM을 보냅니다. 다시 초대하면 관리자가 재개합니다. |
| 그 밖의 발송 실패 | 앱 설치자에게 DM을 보냅니다. |

앱 설치자가 퇴사하거나 바뀔 때는 앱 설치자가 다른 사람에게 넘깁니다.

## 제약 사항

무료 개인 Gmail 계정으로 운영하며, 일정을 미리 계산해 두는 방식으로 알림 오차를 약 1분 안쪽으로 맞춥니다.

| 항목 | 제약 |
| --- | --- |
| 공용 구글 계정 | 무료 개인 Gmail 계정. 자동 실행 시간이 하루 총 90분으로 제한됩니다([Apps Script 한도](https://developers.google.com/apps-script/guides/services/quotas)). |
| 실행 방식 | 10분마다 모든 캘린더를 읽어 보낼 알림 목록을 만들고, 1분마다 그 목록에서 지금 보낼 알림만 확인합니다. 캘린더가 바뀌면 목록을 바로 다시 만듭니다. 예상 사용량은 하루 약 20분(추정)이며, 구현 후 실제 실행 기록으로 확인합니다. |
| 알림 시각 정확도 | 최대 약 1분 늦습니다. "시작 시간" 알림도 시작 직후에 도착할 수 있습니다. 한도에 가까워지면 확인 주기를 늘리고 오차도 커집니다. |
| 변경 감지 지연 | 구글이 캘린더 변경을 알려 주는 데 몇 초에서 1\~2분이 걸릴 수 있습니다. |
| 요청 검증 | Apps Script는 Slack 표준 서명 검증을 쓸 수 없어 Verification Token으로 확인합니다. Slack이 권장하지 않는 방식이라 언젠가 막힐 수 있습니다. |
| 응답 속도 | Slack은 3초 안에 응답을 요구해서, 가끔 설정 화면이 늦게 열리거나 "응답 없음"이 뜨면 다시 눌러야 합니다. |
| 비공개 채널 | 봇을 먼저 초대해야 알림을 보낼 수 있습니다. |
| 시간대 | 모든 시각은 한국 시간(Asia/Seoul) 기준입니다. |
